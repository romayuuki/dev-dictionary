## 3. REQ-1 — الدمج الذكي عند الاستيراد

### 3.1 المشكلة

`TransferService.importFile` تستدعي `store.appendToCategory` التي تُلحق العقد بلا فحص. استيراد ملف يحوي «React › Component» في قاموس فيه «React › Component» يُنتج نسختين من كليهما.

### 3.2 مفتاح المطابقة

عقدتان تُعتبران **نفس العقدة** إذا تساوى `mergeKey`:

```
mergeKey(node) = normalizeTitle(node.title)
```

حيث `normalizeTitle` تُبنى فوق `text.util.ts` الموجودة وتطبّق بالترتيب:

1. تطبيع عربي (`ا أ إ آ` → `ا` · `ى` → `ي` · `ة` → `ه` · حذف التشكيل والتطويل)
2. `toLowerCase()`
3. حذف المحارف غير الأبجدية الرقمية عدا الفراغ
4. ضغط الفراغات المتتالية إلى واحد و `trim()`

> **قرار**: المطابقة بالعنوان لا بالمعرّف. المعرّفات تُولَّد عشوائياً عند الإدخال اليدوي، فلا تتطابق أبداً بين ملف مستورد وقاموس قائم.

**أمثلة مُلزِمة**:

| العنوان أ | العنوان ب | تطابق؟ |
|---|---|---|
| `React` | `react` | ✅ |
| `المكوّن (Component)` | `المكون (component)` | ✅ |
| `useState` | `useState — إدارة الحالة` | ❌ (نصّان مختلفان) |
| `Props` | `props ` | ✅ |

### 3.3 خوارزمية الدمج

```
mergeNodes(existing[], incoming[], report) → existing[]

لكل node in incoming:
  match ← existing.find(e => mergeKey(e) === mergeKey(node))

  إن لم يوجد match:
    existing.push(node)               // عقدة جديدة كاملة بشجرتها
    report.added++
    continue

  // ── دمج في الموجود ──
  match.def      ← mergeDef(match.def, node.def)
  match.tags     ← unionTags(match.tags, node.tags)
  match.examples ← mergeExamples(match.examples, node.examples)
  match.children ← mergeNodes(match.children ?? [], node.children ?? [], report)   // تعاودي
  إن كان لـ match أبناء ⇒ match.kind ← 'group'
  report.merged++

return existing
```

**القواعد الفرعية**:

| الحقل | القاعدة |
|---|---|
| `def` | إن كان الموجود فارغاً ← خذ الوارد. إن تطابق نصّياً بعد التطبيع ← لا تفعل شيئاً. وإلا ← ألحِق الوارد بعد فاصل `\n\n---\n\n`. **لا يُستبدَل نصّ المستخدم أبداً.** |
| `tags` | اتحاد بلا تكرار، المقارنة بـ `normalizeTitle` |
| `examples` | دمج بمفتاح `hash(code)` — مثال بنفس الكود لا يتكرّر ولو اختلف عنوانه |
| `children` | استدعاء تعاودي لنفس الخوارزمية |
| `id` | **يُحتفظ بمعرّف الموجود دائماً** — حتى لا تنكسر الروابط `[[id\|نص]]` |
| الترتيب | العقد المدموجة تبقى في مواضعها؛ الجديدة تُلحق في النهاية |

### 3.4 المعاينة قبل التنفيذ (مبدأ P2)

`mergeNodes` تُنفَّذ أولاً على **نسخة** (`deepClone`) لبناء التقرير، ثم تُعرض نافذة:

```
📥 معاينة الاستيراد — Frontend

  ⤵ جديد   React            9 عقد
  ⤿ دمج    React › Component   ← تعريفك محفوظ، +2 مثال
  ⤿ دمج    React › Props       ← +1 وسم

  الإجمالي:  8 جديدة · 2 مدموجة · 0 محذوفة

  [ إلغاء ]                        [ تأكيد الاستيراد ]
```

- الشجرة قابلة للطي وتعرض 50 صفاً كحد أقصى ثم «و N أخرى».
- سطر `0 محذوفة` **ثابت دائماً** — تأكيد بصري على مبدأ P1.
- لا تُطبَّق أي تعديلات قبل الضغط على «تأكيد».

### 3.5 التراجع

قبل تطبيق الدمج تُحفَظ نسخة في `LS_UNDO_IMPORT` مع طابع زمني. يظهر Toast لمدة **10 ثوانٍ** بزر «تراجع» يستعيد النسخة عبر `store.replaceAll`. تُمسَح النسخة عند أول تعديل يدوي لاحق.

## 4. REQ-2 — تحريك العقد

### 4.1 العمليات

| العملية | السلوك | مُعطَّلة عندما |
|---|---|---|
| **أعلى** ↑ | تبادل مع الشقيق السابق | أول عنصر |
| **أسفل** ↓ | تبادل مع الشقيق التالي | آخر عنصر |
| **إدخال** → | تصير آخر ابن للشقيق السابق | لا يوجد شقيق سابق |
| **إخراج** ← | تصير الشقيق التالي لأبيها | الأب قسم رئيسي |
| **نقل إلى…** | نافذة اختيار أب جديد | — |

> اتجاه الأسهم في الواجهة معكوس بصرياً لتوافق RTL؛ الدلالة كما أعلاه.

### 4.2 حماية إلزامية

```
moveToParent(nodeId, newParentId):
  إن كان newParentId داخل شجرة nodeId  ⇒ ارفض (حلقة)
  إن كان newParentId === nodeId        ⇒ ارفض
```

الفحص عبر `store.walk` قبل أي تعديل. الرفض يُظهر Toast: «لا يمكن نقل عنصر داخل نفسه».

### 4.3 الواجهة

- الأزرار تظهر **عند التركيز أو المرور** على العقدة (لا تزحم العرض الافتراضي).
- كل زر ≥ 44×44px (NFR-4)، له `[attr.aria-label]` وصفي.
- اختصارات لوحة المفاتيح على عقدة مركَّز عليها: `Alt+↑` `Alt+↓` `Alt+→` `Alt+←`.
- **سحب وإفلات** (سطح المكتب فقط): HTML5 Drag & Drop الأصلي — **لا** يُضاف `@angular/cdk` (NFR-1). مؤشر إفلات: خط أفقي بين العقد للترتيب، وإطار حول العقدة للإدخال بداخلها.
- بعد كل حركة: تمرير سلس للعقدة + وميض `flash` (نفس آلية `scrollToNode` القائمة).

### 4.4 واجهة برمجية

## 5. REQ-3 — محتوى غني داخل التعريفات

### 5.1 قرار البنية

**التعريف يبقى حقل نصّ واحد (`def: string`).** لا حقول جديدة في نموذج البيانات.

> **لماذا؟** أي بنية مركّبة تكسر البحث (`search.service.ts` تفهرس `def` كنص)، وتكسر التصدير، وتُلزِم ترحيلاً معقّداً. النصّ المُعلَّم يحقّق الهدف بصفر تكلفة بنيوية — وهو تطبيق مباشر لمبدأ P4.

**نتيجة**: لا حاجة لـ v7 فعلياً. **نسخة البيانات تبقى v6.** (يُلغى ما ورد في ترويسة هذه الوثيقة عن v7.)

### 5.2 الصياغة المدعومة داخل `def`

الموجود حالياً: `**عريض**` · `` `كود سطري` `` · `[[id|نص]]` · جداول.

**الإضافات**:

| العنصر | الصياغة | العرض |
|---|---|---|
| قائمة نقطية | سطر يبدأ بـ `- ` أو `• ` | `<ul><li>` |
| قائمة مرقّمة | سطر يبدأ بـ `1. ` | `<ol><li>` |
| كتلة كود | ` ```lang ` … ` ``` ` | كتلة داكنة + تلوين + زر نسخ |
| سهم | المحرف مباشرة (`⟶` `⇒` `⤳` `↳`) | `<span class="arrow">` بحجم ووزن مضبوطين |
| مخطط | ` ```mermaid ` … ` ``` ` | REQ-5 |

القوائم المتتالية تُجمَّع في `<ul>` واحدة. التداخل بمسافتين.

### 5.3 التنفيذ

- التوسعة في `text.util.ts › formatDef` — نفس الدالة المستخدَمة في العرض حالياً.
- **تلوين الصياغة**: يُحمَّل highlighter خفيف من CDN **عند أول ظهور كتلة كود في الصفحة** عبر `IntersectionObserver` (NFR-2). قبل التحميل تُعرض الكتلة بخط ثابت بلا تلوين — لا وميض ولا إزاحة تخطيط.
- **التنقية**: الناتج يمرّ بمُنقٍّ بقائمة سماح: `p, br, strong, em, code, pre, ul, ol, li, table, thead, tbody, tr, th, td, span, a`. السمات المسموحة: `class`, `data-lang`, `data-color`, `data-size`, `href` (بمخطط `https:` فقط). كل ما عداه يُحذف (NFR-5).

## 6. REQ-4 — المحرر المرئي

### 6.1 المشكلة الحالية

`node-editor.component.ts` يطبّق التنسيق بإدراج علامات نصّية في `<textarea>`، فتظهر للمستخدم أثناء الكتابة. يخالف P3.

### 6.2 الحل

استبدال `<textarea>` بـ `<div contenteditable="true">` مع طبقتين:

```
DOM المعروض (غني)  ←→  النصّ المُعلَّم (المصدر)
      ↑ العرض والتحرير          ↑ ما يُحفَظ في def
```

- **عند الفتح**: `def` → HTML عبر `formatDef` نفسها (مصدر واحد للعرض).
- **عند التنسيق**: تُطبَّق على `Range` المحدّد بإحاطة الجزء بـ `<span data-color>` أو `<span data-size>` — **بلا** `document.execCommand` (مهجورة وغير متسقة).
- **عند الحفظ**: HTML → نصّ مُعلَّم عبر مُسلسِل معاكس، ثم تنقية §5.3.

### 6.3 شريط الأدوات

مجموعات مفصولة، كل زر ≥ 44×44px مع `[attr.aria-label]`:

```
[ B ] [ I ] [ </> ]  │  [🎨 لون ▾] [🅰 حجم ▾]  │  [• قائمة] [1. ترقيم]  │  [⟶ سهم ▾] [🔗 رابط] [📊 مخطط]
```

**لوحة الأسهم** — بديل جميل عن `=>` المتقطّع:

| المحرف | الاسم | الاستخدام |
|---|---|---|
| `⟶` | سهم طويل | التسلسل والتحويل |
| `⇒` | سهم مزدوج | النتيجة المنطقية |
| `⤳` | سهم متعرّج | التأثير غير المباشر |
| `↳` | سهم متفرّع | التفرّع والتفصيل |
| `⟷` | ثنائي الاتجاه | العلاقة المتبادلة |

تُعرض بـ `class="arrow"`: `font-size: 1.15em` · `vertical-align: -0.05em` · `margin: 0 .25em` · `color: var(--fg-2)` · `direction: ltr; unicode-bidi: isolate` (حرجة في RTL).

## 7. REQ-5 — المخططات

### 7.1 القرار

**Mermaid** عبر كتلة ` ```mermaid `.

| البديل | الحكم |
|---|---|
| **Mermaid** | ✅ نصّي (P4) · قابل للبحث · ~40KB مضغوط · يُحمَّل كسولاً |
| Excalidraw | ❌ ثنائي، غير قابل للبحث، +500KB — يخالف P4 و NFR-1 |
| رفع صور | ❌ تكلفة تخزين ومزامنة، خارج النطاق |

### 7.2 التنفيذ

- يُحمَّل من CDN **فقط** عند وجود كتلة `mermaid` ظاهرة (`IntersectionObserver`)، مرة واحدة لكل جلسة.
- فشل التحميل أو خطأ صياغة ⇒ تُعرض الكتلة كنصّ عادي داخل إطار تنبيه لطيف. **لا تعطُّل**.
- ألوان المخطط من متغيّرات الثيم (`--c`, `--fg`, `--bg`) لتتبع الوضع الليلي.
- المخطط داخل `<figure>` بـ `content-visibility: auto` للحفاظ على أداء التمرير.

### 7.3 معايير القبول

| # | المعيار |
|---|---|
| AC-5.1 | صفحة بلا مخططات ⇒ Mermaid لا يُحمَّل إطلاقاً |
| AC-5.2 | صياغة خاطئة ⇒ نصّ + تنبيه، بلا انهيار |
| AC-5.3 | نصّ المخطط قابل للبحث |
| AC-5.4 | تبديل الثيم ⇒ ألوان المخطط تتبع |

| السحب والإفلات على اللمس | إحباط | الأزرار هي الطريق الأساسي؛ السحب تحسين لسطح المكتب فقط |

## 10. ملخّص التغييرات على البيانات

**لا تغيير في نموذج البيانات.** تبقى النسخة **v6**.

كل مزايا SPEC-003 تعمل على البنية القائمة (`DictNode` كما هي). ما يتغيّر: منطق الاستيراد، وطبقة العرض، والمحرر. هذا مقصود — أقل خطر على بيانات قائمة يعتمد عليها المستخدم يومياً.
